# Участие в разработке

Спасибо, что хотите помочь. Здесь — как предложить изменение так, чтобы его было легко принять.

Участвуя в проекте, вы соглашаетесь с [кодексом поведения](CODE_OF_CONDUCT.md). Об уязвимостях сообщайте
приватно, по [политике безопасности](SECURITY.md), а не в issues.

## Прежде чем писать код

- **Баг** — откройте issue по шаблону: версия пакета, способ подключения, шаги и что ожидали. Минимальный
  пример экономит больше всего времени.
- **Новая возможность или изменение API** — сначала обсудите в issue. Пакет намеренно маленький, и
  изменение, которое меняет публичный API или поведение по умолчанию, лучше согласовать до реализации.
- Мелкие исправления — опечатки, README, очевидные баги — можно присылать сразу pull request'ом.

## Окружение

Нужен Node 22.18+ (версия для CI — в `.nvmrc`): конфиги сборки и тестов — TypeScript без загрузчика.

```bash
npm ci
npm run check
```

`npm run check` — то же, что проверяет CI: формат (Prettier), линт (ESLint), типы, тесты (Jest), сборка,
запуск каждого собранного бандла так, как его подключает потребитель, проверка типов пакета (`attw`) и
компиляция примеров из README. Отдельно CI прогоняет типы и тесты на нижней границе `peerDependencies`:

```bash
npm run verify:peers-floor
```

Хелперы вёрстки CI проверяет ещё и в настоящих браузерах — на картинках, которые отдаёт локальный сервер
(`browser-tests/`). Перед первым запуском поставьте браузеры, сам прогон идёт по собранному бандлу:

```bash
npx playwright install chromium firefox webkit
npm run build && npm run verify:browsers
```

## Как писать код

- **Без комментариев по умолчанию.** Смысл несут имена, типы и структура. Комментарий уместен, только если
  из кода не видно причину: обход бага библиотеки, ограничение браузера, контракт Faro.
- **Тест — на поведение, которое важно пользователю.** Спросите себя, какую реальную поломку тест поймает.
  Утверждения — о наблюдаемом результате (отправленная метрика, состояние трекера, очищенный URL), а не о том,
  что «функция вызвалась». Тесты через настоящий Faro — в `src/testing/realFaro.ts`.
- **README — часть контракта.** Меняете поведение — поправьте README; примеры кода в нём компилируются
  в `npm run check`.
- Код должен работать в ES2019-браузерах и в `dist/index.umd.full.js` без сборщика у потребителя.

## Коммиты и pull request

- Заголовок коммита — по-английски, в прошедшем времени, о том, что изменилось для пользователя:
  `Fixed SLO runs resuming in hidden tabs`. В теле — зачем, если это не очевидно.
- Один pull request — одна задача. Заполните шаблон и убедитесь, что `npm run check` проходит.
- Не поднимайте версию в `package.json` — релиз делает мейнтейнер по git-тегу.
